# russian-chat-bench

Бенчмарк локальных LLM на **живом русском разговоре**: модель получает фиксированный сценарий из 6 реплик (тесты на контекст, сленг, юмор, сарказм, эмоциональные противоречия) и просьбу о пересказе, а ответы оцениваются по пониманию контекста, юмору, естественности и по тому, есть ли лекции. Отдельно замеряются скорость, задержки и пик RAM.

Режимы:
- **напрямую**: русский вопрос → модель → русский ответ;
- **через переводчик**: вопрос RU→EN переводчиком → модель отвечает по-английски → ответ EN→RU переводчиком. Переводчик — Hy-MT2-1.8B.

Сценарий, промпты и результаты описаны ниже. Все прогоны — llama.cpp `b11889`, CPU, Windows.

## Сценарий

Файл `scripts/dialog-scenario.mjs`. Реплики пользователя фиксированы, ответы модели — нет.

1. Живой разговор: день «дурдом», друг зовёт встретиться, вопрос «остаться дома или выбраться» без лекций.
2. Понимание контекста: «батарейка села, не из-за лени, что бы ты сделал? Только не повторяй то же другими словами».
3. Разговорная естественность: попросить короткое сообщение другу, без официоза, с подколом.
4. Дружеские подколы: друг написал «о, какие люди!.. в Красную книгу занесли 😂» — понимает ли модель, всерьёз это или нет.
5. Эмоциональное противоречие: «сам решил выбраться, а злюсь, будто меня тащат», без «внутреннего ребёнка».
6. Скрытый смысл и сарказм: друг написал «без историй про начальника, а то я сам на больничный уйду 😂», просьба сказать как есть.
7. Просьба: краткий пересказ всего разговора, 4–6 предложений.

Память диалога — 8 последних сообщений. Системные промпты нейтральные, без упоминания русского языка:
- русский: «Ты собеседник в живом разговоре. Отвечай естественно, как человек: коротко, без markdown, списков и заголовков.»
- английский (для режима через переводчик): «You are a conversation partner. Reply naturally, like a person: short, no markdown, lists or headings.»

Переводчик Hy-MT2 использует формат из карточки модели (профиль `hymt`): без system-промпта, инструкция в сообщении пользователя.

## Что замеряется

- **RAM** — пик рабочего набора процесса `llama-server` за весь диалог (`PeakWorkingSet64`, Windows) и значение сразу после загрузки. Для mmap это примерно размер файла плюс буферы контекста. Отдельно — пик процесса переводчика.
- **Скорость мозга** — токены в секунду из поля `timings` ответа llama-server (`predicted_per_second`), а при его отсутствии — по `usage` и времени генерации.
- **Время до первого токена** и **время генерации**.
- В режиме через переводчик: **перевод вопроса** (RU→EN), **хвост перевода ответа** (сколько EN→RU тянется после окончания ответа мозга, при переводе по предложениям), **первая русская фраза** от отправки и **итого**.
- **Загрузка** модели в секундах.

## Как запустить

Нужны Node.js ≥ 20.19 и сборка llama.cpp: [релиз b11889](https://github.com/ggml-org/llama.cpp/releases/tag/b11889), файл `llama-b11889-bin-win-cpu-x64.zip`. Зависимостей npm нет.

```powershell
# где лежат модели и llama.cpp (по умолчанию D:\localai\llm)
$env:LLM_HOME = 'D:\localai\llm'
$env:LLAMA_SERVER = 'D:\localai\llm\llama.cpp\b11889\llama-server.exe'   # необязательно, если путь по умолчанию

npm run llm -- list                      # что есть на диске
npm run llm -- pull qwen3.5-4b hymt2-1.8b  # скачать с Hugging Face с проверкой размера и SHA-256

npm run bench:dialog                     # все модели из списка заданий
npm run bench:dialog -- qwen3.5-4b       # одна модель (оба режима, если категория 1)
```

Результаты пишутся в `reports/` (отчёты `<модель>.md`, `таблица.md`, данные в `reports/data/`). Рабочие данные чата складываются в `data-dialog/` и в git не попадают.

Бенч на 14 вопросах (`scripts/bench.mjs`, вопросы в `scripts/questions.ru.json`) — более ранний и короткий. Он проверял одиночные вопросы, а не диалог. Результаты в `results/compare/`: запуски с разными версиями промпта Hy-MT, поэтому сравнивайте внутри одного файла, а не между ними.

Переменные окружения:
- `LLM_HOME` — папка с `models/` и `llama.cpp/`;
- `LLAMA_SERVER` — путь к `llama-server.exe`;
- `LLM_ENV_FILE` — необязательный `.env` с `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`, если хотите сравнить облачную модель. Для локальных моделей не нужен.

Роли по портам: мозг — `127.0.0.1:8180`, переводчик — `127.0.0.1:8181`. Бенч поднимает и останавливает серверы сам.

## Ограничения

- **Один прогон на модель.** Ответы сэмплируются, поэтому другой прогон даст другие очки. Для уверенного ранжирования нужно минимум 3 прогона.
- **Очки ставил один оценщик** (я) и не вслепую. Читайте диалоги в `results/dialog/<модель>.md` и ставьте свои оценки.
- **Один сценарий**: 6 реплик. Длинные диалоги и память за 8 сообщений не проверяются.
- **Замеры на одной машине** (Ryzen 7 7700, 32 ГБ, без GPU, Windows 11). Время и RAM на другом железе будут другими.
- **Пик RAM** — рабочий набор процесса, а не выделенная память. Аномалия: GigaChat Q4_K_M весит 6 ГБ, а пик у него 10,9 ГБ, тогда как Q6 (8,2 ГБ) даёт 8,4 ГБ. Причину не выясняли.
- **Облачные модели** в бенч не входят. Прогоны на облачном мозге из первых тестов не публикуются.

```
  llm.mjs              список, скачивание и запуск моделей
results/
  dialog/              итоги, таблица, отчёты по моделям, сырые данные
  compare/             бенч на 14 вопросах (JSON)
```
